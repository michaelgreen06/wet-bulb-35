# Cloudflare edge crawler/redirect candidate — not installed

`node scripts/build-edge-crawler-policy.mjs` emits **candidate rule objects only**. It never changes Cloudflare. This branch must not be merged or used for production without a separate access, backup, staging and rollback review.

## Why these rules

- During 2026-10-17 00:00–10:00 UTC, Cloudflare adaptive analytics grouped 65,544 HTTP 308 responses on `www.wetbulb35.com`: 64,358 had a ShapBot user agent. Joining every grouped path to the checked-in historical-redirect registry found **one request** for a different-destination alias, and **none** among ShapBot requests. Edge request estimates are not the billable Worker counter.
- The registry nevertheless contains 129,080 historical alias sources. A blanket append-slash rule would silently intercept many valid historical routes if someone requests them later. The candidate targets 18 known country-first prefixes that have **zero** historical alias-source intersections, covering 60,012 current city routes and 40,791 of those 64,358 observed ShapBot redirects. After ShapBot is blocked, expected redirect savings are much smaller and must be remeasured.
- The verified ShapBot rule includes an explicit Cloudflare `Search Engine Crawler` exclusion. The separate search-engine rule skips **only** rate limiting, not WAF protections; it must be reviewed against the *existing* zone rate rules before activation. It does not impose a crawler rate limit itself.

## Known differences and release gates

1. **Access:** current token is read-only for zone analytics and gets HTTP 403 for WAF and Redirect Rules entrypoints; browser is signed out. Do not invent current rule IDs, quota headroom, or an installed state. Obtain zone-scoped WAF/Rulesets read+write access securely or use an authenticated live dashboard. Read and back up both existing phase entrypoint rulesets, plus any old settings/rule order, *before* edits. Preserve every unrelated rule. Michael authorized the ShapBot block, search exemption, and redirect fix; that authorization does not waive the backup, staging, and parity gates or authorize other rule changes.
2. **WAF test:** Cloudflare Trace with verified ShapBot and verified Google/Bing requests (or actual known-verified traffic where Trace cannot simulate verification). Confirm the ShapBot block executes before either Worker, and that the search-engine Skip affects only the intended rate-limiting phase. Free AI Crawl Control can also block ShapBot by user agent, but that alternative is not the same as verified-WAF matching; choose one mechanism, not duplicate blocks.
3. **Redirect test:** test the candidate expression with Cloudflare Trace or an isolated subdomain in the same zone: GET/HEAD, query strings, Unicode/encoded paths, double slashes, legacy aliases, recognized and invalid canonical routes, APIs/assets, slash-terminated paths, HSTS/security headers, and custom-domain Worker precedence. Existing Worker 308 responses carry `Strict-Transport-Security`; an edge Redirect Rule might not. Preserve security semantics or reject rollout.
4. **404 tradeoff:** a *nonexistent* slashless path beneath an allowlisted country can receive an edge 308 before the destination returns 404. Local tests prove alias safety and route coverage, not this unknown-path parity. Do not enable without accepting or eliminating that difference.
5. **Verification/rollback:** enable one reversible rule at a time, read back the exact rule IDs/expressions, test public URLs and true bot classifications, and compare Worker invocations plus 308/blocked counts before and after. Roll back only the rules created or changed for this experiment, using the backed-up ordering, if SEO/404/security checks fail. No Worker deployment, merge, DNS change, paid upgrade, or data mutation is authorized by this candidate.

Run `node --test tests/edge-crawler-policy.test.mjs` for exhaustive current-city and legacy-source safety checks. Cloudflare expression parsing and live precedence remain unverified until zone access is restored.
