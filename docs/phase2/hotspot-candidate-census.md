# Hotspot candidate census (draft; no release)

The scheduled publisher has a self-imposed `HOTSPOT_RUN_LOCATION_LIMIT=2000`, inclusive of 100 excluded-location recall controls. This is not Open-Meteo's published API-call cap. `scripts/hotspot-provider-budget.mjs` reserves three refinement attempts per location, 2,000 on-view city forecast attempts, and 60 readiness probes: at the present cap the conservative envelope is 8,060 location attempts, below its separate 9,000 guard. A 3,000-location cap would make that envelope 11,060; do not increase the workflow constant without measuring actual weighted provider usage and the shared forecast reserve.

Existing GitHub run logs from October 5–17, 2026 yielded 22 successful per-attempt candidate counts. Selecting the latest successful run per UTC day gives 13 daily counts (mean about 908, range 648–1,487). This is a short, success-biased sample, not a climatology or a guarantee. The October 18 scheduled attempt and two dispatches all exceeded 2,000 *including* controls, but the old failure path did not print the exact count. It is therefore unknown whether a 3,000 cap would have helped.

This branch emits an anonymous JSON record **before** the cap check and before any location refinement, including initialization, discovered candidates, actual controls, total, limit and selection parameters. Each hosted run logs it and retains a tiny `hotspot-candidate-census-RUN_ID` artifact for 90 days even if the cap rejects publication. No city names, paths, coordinates, or per-city values are stored in the record; this introduces no provider requests and does not raise the cap. After enough runs, group records by UTC run date and initialization (so dispatch retries do not masquerade as independent days), report per-attempt counts separately, and measure the share exceeding 2,000 and 3,000 against hot/humid periods. Missing/failed discovery runs are not zero-candidate days.

This is observability only. The October 18 Top-50 expiry is not repaired by this branch; merging requires Michael's separate approval and a hosted-run verification of the failure artifact. Do not silently truncate candidates or advertise an expired ranking as current.
