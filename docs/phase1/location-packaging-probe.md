# Phase 1 location-packaging probe

## Verdict

**Preferred candidate, pending integration:** static-asset shards. The compact country-shard candidate is 7,784,079 bytes raw (2,508,266 gzip) plus a 16,283-byte route manifest: **7,800,362 raw bytes** (2,511,189 gzip). Unlike the prior estimate, every compact row includes collision-safe `outputCitySlug` generated by the production JavaScript route logic. It fits the stated 25 MiB asset limit and uses 225 runtime files, below the 100,000 asset cap. Static assets avoid placing the entire metadata set in the Worker bundle; they are not a final recommendation until a minimal Hono/Workers asset-binding integration test passes. This is not a Worker bundle-size, cold-start, deployment, or benchmark claim.

## Method

`python3 scripts/probe-location-packaging.py --source scripts/resolved_cities.json --runs 5` invokes Node plus the Python standard library. The Node adapter calls the existing `prepareCities` and `getRouteParts` exports from `scripts/prototype-static-generator.mjs`; it does not reimplement `slugify` or collision logic.

The probe writes a temporary production-generated route-identity index, then incrementally decodes the top-level source JSON array in 64 KiB chunks. It validates every source record against that index by source position and writes raw field-preserving country shards, compact country shards, a minified-source candidate, and a route manifest under a `TemporaryDirectory`; all are deleted before the process returns. It emits one bounded JSON object: aggregate metrics, largest shard, hashes, timing summaries, and file-count projections rather than a record per country.

JSON serialization is deterministic (`ensure_ascii=False`, compact separators, stable source order); gzip uses level 9 and `mtime=0`. Directory hashes include sorted filename and content hashes. The test suite uses small temporary input and checks strict incremental parsing (including delimiter and EOF boundaries), malformed records, no persisted artifacts, schema choices, production-generated collision-safe routing identity, deterministic compact hash, and reproducible gzip output.

## Schema comparison

| Candidate | Per-row representation | Retained fields | Dropped fields |
| --- | --- | --- | --- |
| Raw country shard | JSON object | `name`, `resolvedCountryName`, `resolvedAdmin1Code`, `latitude`, `longitude` | none |
| Compact country shard | `[name, admin1, latitude, longitude, outputCitySlug]` inside `{ "v": 1, "r": [...] }` | `name`, `resolvedAdmin1Code`, `latitude`, `longitude`, `outputCitySlug` | `resolvedCountryName`, derived from the manifest selected by the country route |

The manifest records the original country name, production-generated `countrySlug`, and shard filename. The temporary route-identity index records production-generated country/state/city route parts; compact rows retain the collision-safe city part. The probe never implements `slugify` semantics. In the compact representation country remains available as manifest context.

**Route-identity result:** every compact row retains `outputCitySlug` generated by the production JavaScript `prepareCities`/`getRouteParts` path. The full source has **1,419 collision groups** covering **3,014 rows**; those routes are included in this measurement rather than estimated. The collision fixture is an enforced adapter/schema-contract test, not a Python reimplementation of `slugify`. A future renderer that needs per-row country duplication, source-object keys, or fields not present in the current source schema still requires schema review.

## Limitations

- Timings are local Node/Python process timings, not Worker isolate, bundle, network, or cold-start measurements.
- The temporary route-identity index is fully materialized in Node and then Python for validation, so the reported process memory is not a streaming-memory claim. It is not a shipped artifact.
- Peak RSS is process-lifetime Linux `ru_maxrss`; current RSS is sampled from `/proc/self/status`, so neither isolates a single parsing operation.
- Gzip totals are the sum of independently compressed files; delivery compression, cache behavior, and asset-binding access were not tested.
- The probe validates packaging shape, not a real Worker bundle or runtime integration. It makes no claim about a Worker bundle, cold-start, deployment, or benchmark.
- Before static assets are selected, a minimal Hono/Workers asset-binding integration test must cover: a country route, a state route, a unique-city route, both routes in a colliding-city fixture, and a missing route. It must verify asset-binding path lookup and response behavior with the production-generated route identity/index.
